# Thi đua & BXH PRO 20

Frontend: GitHub Pages at https://dohung712.github.io/baocao/.
Backend: Supabase project baocao-thidua-pro. Edge Function thi-dua verifies every session with Auth, then checks the current membership server-side. Database and media are private and accessed only by the backend.

## Roles

- Owner: dohung712@gmail.com. Full access, manage memberships, configure AI.
- Manager: assigned store/group scopes, manage reports and schedules within those scopes.
- Employee: linked staff ID; own records only.

Only the owner creates membership records. New users receive a one-use activation link generated by the owner in Cấp quyền; share it privately with the exact intended email. It creates a session and offers password setup. For the initial owner login, request the email link, copy the link from the email into the verification field, then set a password in the tool. This works even when the Auth redirect URL has not been customized. Never publish activation links, sessions, service keys, AI keys, exports, or migrated data.

## Data and concurrency

Existing Google Sheets data was imported to app_state as a private workbook snapshot. The compatibility engine retains the established business rules and every legacy tab. Browser requests refresh every 20 seconds. The backend filters response data by role, calculates report scores from trusted configuration/history, and uses version comparison to reject concurrent overwrites. Existing reports edited after 22:20 Vietnam time require approval. Each accepted write records an audit event and a private historical snapshot. Old Google Sheets is no longer a live source for this frontend; old Drive attachments remain linked.

The source sheet header of Data_KetQua_Ngay does not match its row layout. The actual row layout is date,staffId,staffName,itemName,actual,rate,starChange,status,compensation. The compatibility engine and email reporting use the actual layout.

## Reports and AI

A ChatGPT scheduled task reads the new database and emails the owner daily at 22:30 Asia/Ho_Chi_Minh. It is independent of whether the website is open. The chat panel always provides scoped statistics. Generative answers require an owner-supplied OpenAI API key through the secure configuration panel; without it, the panel explicitly identifies its deterministic statistics mode. API keys are never returned to the browser.

## Development and verification

Backend entrypoint: backend/index.ts; legacy compatibility: backend/engine.js; authorization and trusted calculation: backend/policy.js. Deploy these three files together as the thi-dua Edge Function. Gateway verify_jwt is false because the function validates tokens with Auth before accessing any data. Only the health endpoint is anonymous.

Local verification used a private migration fixture which must never be committed. Tested import counts, role isolation, forbidden actions, trusted scoring, repeat submissions, cutoff times, scoped chat, and concurrent overwrite rejection. Production tables have RLS enabled and no browser grants; all reads/writes go through the verified backend.
